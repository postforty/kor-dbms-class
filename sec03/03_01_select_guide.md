# Oracle SQL SELECT 조회 기초 실습 가이드

데이터베이스에서 데이터를 검색하고 확인하는 가장 기본적이면서도 중요한 SQL 문법은 `SELECT`입니다. 이번 실습에서는 `SELECT` 문의 기본 구조와 테이블 전체 데이터를 조회하는 방법, 그리고 실무에서 주의해야 할 성능 최적화 원칙을 학습합니다.

---

## # 실습 예제 1 : 전체 컬럼 조회하기

`customers` 테이블의 모든 컬럼과 행 데이터를 조회합니다.

### 1.1 전체 컬럼 조회 쿼리

```sql
-- customers 테이블의 모든 데이터를 조회
SELECT *
FROM customers;
```

---

## 💡 개발자 note!

### 왜 SELECT * 사용을 지양해야 할까요?

`SELECT *`는 테이블의 모든 컬럼을 한 번에 조회할 수 있어 초보자에게는 편리합니다. 하지만 실무 프로젝트에서는 다음과 같은 이유로 `SELECT *` 사용을 권장하지 않습니다.

#### ❶ 불필요한 데이터 조회로 인한 성능 저하

```sql
-- 잘못된 예시 (불필요한 전체 컬럼 조회)
SELECT *
FROM customers
WHERE is_active = 'Y';
```

단순히 '활성 고객'을 조회하는 쿼리인데, 고객의 주소, 가입일, 메모, 탈퇴일 등 사용하지 않는 컬럼까지 모두 조회되어 불필요한 I/O와 네트워크 비용이 발생합니다.

---

> 🎯 **핵심 배움 포인트 (실무 SELECT 작성 권장 사항)**:
> 1. **필요한 컬럼만 명시(Projection)**:
>    - `SELECT customer_id, name, email FROM customers WHERE is_active = 'Y';`처럼 화면이나 로직 처리에 **실제 필요한 최소한의 컬럼만 나열**하여 불필요한 디스크 I/O와 네트워크 대역폭 낭비를 방지합니다.
> 2. **인덱스 스캔 효율화 (Covering Index)**:
>    - 조회 대상 컬럼이 인덱스에 모두 포함되어 있을 경우, 테이블 데이터 블록에 접근하지 않고 인덱스만 읽고 결과를 반환할 수 있어 성능이 획기적으로 향상됩니다. `SELECT *`를 사용하면 인덱스 커버링을 활용할 수 없습니다.
> 3. **스키마 변경에 대한 안정성 보장**:
>    - `SELECT *`를 애플리케이션 코드에 사용하면 테이블에 대용량 컬럼(CLOB, BLOB 등)이 추가되거나 컬럼 순서가 바뀔 때 예기치 않은 메모리 버퍼 초과 또는 매핑 오류가 발생할 수 있습니다.

## # 실습 예제 2 : 특정 컬럼만 조회하기

`customers` 테이블에서 필요한 컬럼(`name`, `phone`)만 지정하여 조회합니다.

### 2.1 특정 컬럼 조회 쿼리

```sql
-- 고객 이름과 전화번호만 조회
SELECT name, phone
FROM customers;
```

> 🎯 **핵심 배움 포인트 (컬럼 프로젝션, Projection)**:
> - `SELECT 컬럼1, 컬럼2, ... FROM 테이블명;` 형태로 원하는 컬럼만 선택하여 데이터를 가져오는 연산을 관계 대수에서 **프로젝션(Projection)**이라고 합니다.
> - 개발자 노트에서 살펴본 것처럼 필요한 컬럼(`name`, `phone`)만 명시하면 데이터 전송량과 I/O 비용을 크게 절감할 수 있으며, 실무 쿼리 작성의 기본 원칙입니다.

## # 실습 예제 3 : 계산식 사용하기

`products` 테이블에서 상품명, 단가, 재고수량을 조회하고, 산술 연산자(`*`)를 사용하여 총 재고 가치(`단가 x 수량`)를 계산한 뒤 별칭(ALIAS)을 부여하여 조회합니다.

### 3.1 계산식 및 별칭 조회 쿼리

```sql
-- 상품명, 단가, 재고수량, 재고가치(단가x수량)를 함께 조회
SELECT name, price, stock_quantity, price * stock_quantity AS "재고가치"
FROM products;
```

> 🎯 **핵심 배움 포인트 (산술 연산과 별칭, ALIAS)**:
> - **SELECT 절 내 산술 연산**: 컬럼 값에 사칙연산(`+`, `-`, `*`, `/`)을 적용하여 새로운 가상 컬럼(파생 데이터)을 즉시 계산하고 조회할 수 있습니다.
> - **컬럼 별칭 (`AS "별칭"`)**:
>   - 수식을 그대로 두면 결과 헤더가 수식 형태(`PRICE*STOCK_QUANTITY`)로 표시되어 직관적이지 못합니다.
>   - `AS` 키워드를 통해 의미 있는 별칭을 부여하면 결과 확인 및 애플리케이션 매핑이 수월해집니다.
>   - Oracle SQL에서는 **한글, 공백, 특수문자가 포함된 별칭이나 영문 대소문자를 구분해야 할 때 큰따옴표(`""`)**를 필수적으로 사용합니다.

## # 실습 예제 4 : 컬럼 이름을 한글로 바꾸기

`customers` 테이블의 영문 컬럼명(`name`, `phone`)을 직관적인 한글 별칭(`고객명`, `연락처`)으로 변환하여 조회합니다.

### 4.1 한글 별칭 조회 쿼리

```sql
-- 고객 이름과 전화번호를 한글 별칭으로 조회
SELECT name AS "고객명", phone AS "연락처"
FROM customers;
```

> 🎯 **핵심 배움 포인트 (식별자 따옴표 구분: 큰따옴표 vs 작은따옴표)**:
> - **큰따옴표 (`""`)**: 컬럼 별칭(ALIAS)이나 테이블명 같은 **데이터베이스 식별자(Identifier)**를 감쌀 때 사용합니다. 한글, 띄어쓰기, 특수문자 표기 및 대소문자 구분을 유지하려면 반드시 큰따옴표를 사용해야 합니다.
> - **작은따옴표 (`''`)**: 문자열 데이터(리터럴 상수, 예: `'홍길동'`, `'Y'`)를 나타낼 때만 사용합니다.
> - ⚠️ **주의**: 별칭을 부여할 때 작은따옴표(`'고객명'`)를 사용하면 Oracle 문법 오류(`ORA-00923: FROM keyword not found where expected`)가 발생하므로 반드시 큰따옴표를 사용하거나 특수조건이 없다면 따옴표 없이 사용합니다.

---

## # 실습 예제 5 : 계산 결과에 별칭 붙이기

`products` 테이블의 기본 컬럼들과 계산식(`price * stock_quantity`) 모두에 각각 직관적인 한글 별칭을 부여하여 완성도 높은 조회 결과를 생성합니다.

### 5.1 계산식 및 다중 컬럼 별칭 조회 쿼리

```sql
-- 단가 x 수량 = 재고 가치 계산
SELECT name AS "상품명",
       price AS "가격",
       stock_quantity AS "재고량",
       price * stock_quantity AS "재고가치"
FROM products;
```

> 🎯 **핵심 배움 포인트 (다중 컬럼 별칭과 쿼리 포맷팅)**:
> - **일반 컬럼과 계산식 컬럼의 통합 별칭**: 기본 컬럼(`name`, `price`, `stock_quantity`)과 연산식 컬럼(`price * stock_quantity`) 모두에 명확한 한글 별칭을 일관되게 적용하여 비즈니스 보고서에 바로 활용 가능한 결과 셋을 만듭니다.
> - **SQL 가독성을 위한 줄바꿈 및 인덴트**: 여러 컬럼과 계산식을 나열할 때는 한 줄로 길게 늘어놓지 않고, 컬럼 단위로 개행하여 들여쓰기(Indent)를 적용하는 것이 실무 SQL 작성 및 협업의 표준입니다.

## # 실습 예제 6 : AS 생략하기 (권장하지 않음)

별칭을 지정할 때 `AS` 키워드를 생략하고 공백으로 구분하여 별칭을 부여할 수 있습니다.

### 6.1 AS 키워드 생략 쿼리

```sql
-- 별칭 사용 시 AS는 생략 가능
SELECT name "고객이름", email "이메일주소"
FROM customers;
```

> 🎯 **핵심 배움 포인트 (AS 생략 가능 여부와 실무 권장 사항)**:
> - **문법적 허용**: SQL 표준 및 Oracle에서는 컬럼명 뒤에 `AS`를 쓰지 않고 띄어쓰기 후 별칭을 기술해도 정상 동작합니다.
> - **실무에서 생략을 권장하지 않는 이유**:
>   1. **콤마(`,`) 누락 실수와의 혼동**: 개발자가 두 번째 컬럼을 조회하려고 콤마를 빠뜨렸을 때(예: `SELECT col1 col2 FROM ...`), SQL 엔진은 `col2`를 두 번째 컬럼이 아니라 `col1`의 별칭으로 인식하여 조용히 잘못된 쿼리를 실행해 버립니다.
>   2. **코드 가독성과 의도 전달**: `AS` 키워드를 명시하면 컬럼의 조회와 별칭 부여 의도가 시각적으로 명확히 분리되어 팀 내 코드 리뷰와 유지보수에 훨씬 유리합니다.

---

## 💡 개발자 note!

### 별칭(Alias) 활용 팁

- 컬럼명을 직접 변경할 수는 없지만, **별칭(alias)**을 통해 출력 결과의 컬럼명을 임시로 변경할 수 있습니다.
- BI 보고서, 통계표, 고객 응답용 자료에서는 별칭을 적극적으로 활용하면 가독성과 전달력이 크게 향상됩니다.
- SQL에서 사용하는 별칭은 일시적인 것이며, 테이블 구조나 컬럼 정의에는 영향을 주지 않습니다.
- 별칭에 공백이나 특수문자(예: 한글, 공백, 특수기호 등)가 포함되는 경우에는 반드시 큰따옴표(`""`)로 감싸야 합니다.  
  *(예: `"고객명"`, `"재고가치(원)"`, `"E-mail 주소"` 등)*

## # 실습 예제 7 : 특정 이름으로 검색하기 (문자열)

문자열을 비교할 때는 반드시 작은따옴표(`' '`)를 사용해야 합니다. `WHERE` 절을 사용하여 고객 테이블에서 이름이 '김하늘'인 데이터만 필터링하여 조회합니다.

### 7.1 문자열 조건 검색 쿼리

```sql
-- 이름이 '김하늘'인 고객만 조회
SELECT *
FROM customers
WHERE name = '김하늘';
```

> 🎯 **핵심 배움 포인트 (WHERE 절과 문자열 리터럴 규칙)**:
> - **조건 검색(Selection)**: `WHERE` 절을 통해 특정 조건을 만족하는 행(Row)만 선별적으로 추출할 수 있습니다.
> - **문자열 표기 (`' '`)**:
>   - SQL에서 문자열 데이터나 날짜 데이터는 **반드시 작은따옴표(`' '`)**로 감싸야 합니다.
>   - 만약 큰따옴표(`"김하늘"`)를 사용하면 Oracle 엔진은 이를 데이터 값이 아닌 **컬럼 식별자**로 인식하여 `ORA-00904: "김하늘": invalid identifier` 오류가 발생합니다.
> - **대소문자 구분**: Oracle Database는 영문 문자열 비교 시 대소문자를 엄격히 구분하므로 주의해야 합니다. (예: `'admin'`과 `'Admin'`은 서로 다른 값)

## # 실습 예제 8 : 가격이 15,000원 이상인 상품 검색하기 (숫자)

숫자 데이터는 따옴표 없이 비교 연산자(`>`, `<`, `>=`, `<=`, `=`)를 사용합니다. `products` 테이블에서 단가(`price`)가 15,000원 이상인 상품의 이름과 가격을 조회합니다.

### 8.1 숫자 비교 조건 검색 쿼리

```sql
-- 단가가 15,000원 이상인 상품을 조회
SELECT name, price
FROM products
WHERE price >= 15000;
```

> 🎯 **핵심 배움 포인트 (숫자 리터럴 표기와 비교 연산자)**:
> - **따옴표 및 기호 생략**: 숫자 데이터는 따옴표 없이 숫자만 작성합니다. 특히 천 단위 쉼표(`,`)를 포함하여 `15,000`으로 적으면 문법 오류가 발생하므로 반드시 `15000`과 같이 순수 숫자만 입력해야 합니다.
> - **비교 연산자 활용**:
>   - `>=` (이상), `<=` (이하), `>` (초과), `<` (미만), `=` (같다), `!=` 또는 `<>` (같지 않다)
> - **숫자 인덱스 활용**: 숫자 컬럼에 조건 비교를 수행할 때 컬럼 가공(`price * 1.1 >= 15000` 등)을 하지 않고 원본 컬럼 형태를 유지해야 해당 컬럼에 생성된 B-Tree 인덱스를 최적으로 활용할 수 있습니다.

## # 실습 예제 9 : 특정 날짜 이후 주문한 고객 조회하기

날짜 데이터 역시 문자열처럼 작은따옴표로 감싸서 표현하는 것이 일반적입니다. `orders` 테이블에서 주문 일자(`order_date`)가 2025년 6월 1일 이후인 주문 내역을 조회합니다.

### 9.1 날짜 조건 검색 쿼리

```sql
-- 2025년 6월 1일 이후의 주문 데이터 조회
SELECT order_id, customer_id, order_date
FROM orders
WHERE order_date >= '2025-06-01';
```

> 🎯 **핵심 배움 포인트 (날짜 데이터 비교 원리와 NLS 설정)**:
> - **날짜 리터럴 표기**: SQL에서 날짜 데이터는 문자열과 마찬가지로 **작은따옴표(`' '`)**로 감싸서 표기합니다.
> - **시간 정보 주의 (자정 기준)**: `'2025-06-01'`처럼 날짜만 작성하면 기본적으로 자정(`2025-06-01 00:00:00`)으로 해석됩니다. 따라서 6월 1일 당일의 모든 주문을 포함하여 검색할 수 있습니다.
> - **실무 팁 (명시적 형변환 권장과 NLS)**:
>   - **NLS(National Language Support)**: Oracle에서 언어, 지역, 문자셋 및 날짜/통화 표기 방식을 제어하는 환경 설정(파라미터)입니다.
>   - 시스템/클라이언트의 날짜 포맷 설정(`NLS_DATE_FORMAT`)에 따라 `'2025-06-01'` 문자열 형식이 오류를 유발할 수 있으므로, 실무에서는 `TO_DATE('2025-06-01', 'YYYY-MM-DD')` 또는 ANSI 리터럴인 `DATE '2025-06-01'`을 사용하는 것이 안전합니다.

## 3.1 비교 연산자(관계 연산자)

비교 연산자는 값과 값을 비교하여 참(TRUE) 또는 거짓(FALSE)을 판단하는 연산자입니다.  
다음은 `WHERE` 절에서 가장 기본적으로 사용되는 조건 표현 방식입니다.

| 연산자 | 의미 | 예시 |
| :---: | :--- | :--- |
| `=` | 같다 | `WHERE name = '홍길동'` |
| `!=`, `<>` | 같지 않다 | `WHERE price <> 10000` |
| `>`, `<` | 크다, 작다 | `WHERE stock_quantity > 50` |
| `>=`, `<=` | 이상, 이하 | `WHERE rating >= 4` |

> 🎯 **핵심 배움 포인트 (비교 연산자와 NULL 주의사항)**:
> - **NULL 비교 시 주의**: `NULL`은 '값이 존재하지 않음' 또는 '알 수 없음(UNKNOWN)'을 의미하므로 `=`나 `!=` 같은 일반 비교 연산자로는 참/거짓을 판정할 수 없습니다. NULL 값을 검색할 때는 반드시 `IS NULL` 또는 `IS NOT NULL` 구문을 사용해야 합니다.
> - **부정 비교 연산자**: SQL에서 '같지 않다'를 표현할 때 `!=`, `<>`, `^=` 3가지 모두 사용 가능하며, 실무에서는 가독성과 호환성을 위해 `!=` 또는 `<>`가 주로 쓰입니다.

## 3.2 논리 연산자

논리 연산자는 비교 연산자로 만든 여러 조건을 연결할 때 사용하는 연산자입니다.  
조건식의 결과는 참(TRUE) 또는 거짓(FALSE)으로 평가됩니다.

| 연산자 | 의미 | 설명 |
| :---: | :--- | :--- |
| **`AND`** | 그리고 | 모든 조건이 참일 때만 참 |
| **`OR`** | 또는 | 조건 중 하나라도 참이면 참 |
| **`NOT`** | 부정 | 조건의 결과를 부정 |

> 🎯 **핵심 배움 포인트 (논리 연산자 우선순위와 괄호 활용)**:
> - **연산자 평가 우선순위**: `NOT` > `AND` > `OR` 순서로 평가됩니다.
> - **괄호 `()`의 필수적 활용**: `AND`가 `OR`보다 먼저 실행되므로, `OR` 연산자를 먼저 평가해야 하거나 복합적인 조건식이 결합될 때는 반드시 괄호 `( )`로 묶어 우선순위를 명시해야 의도치 않은 논리 오류를 방지할 수 있습니다.

## # 실습 예제 12 : AND 연산자 (교집합) 가격과 재고 조건을 동시에 만족하는 상품 조회하기

AND 연산자는 두 가지 조건을 모두 만족해야 하는 경우입니다. 보통 검색 범위를 좁힐 때 사용합니다. `products` 테이블에서 가격이 10,000원 이상이면서 재고가 50개 이하인 상품을 조회합니다.

### 12.1 AND 조건 검색 쿼리

```sql
-- 가격이 10,000원 이상이면서, (그리고) 재고가 50개 이하인 상품의 상품명, 가격, 재고량 조회
SELECT name, price, stock_quantity
FROM products
WHERE price >= 10000 AND stock_quantity <= 50;
```

> 🎯 **핵심 배움 포인트 (AND 연산과 검색 범위 축소)**:
> - **동시 만족 (교집합)**: 나열된 모든 조건이 `TRUE`일 때만 결과에 포함됩니다. 조건이 늘어날수록 검색 결과 집합은 축소(정밀 타깃팅)됩니다.
> - **복합 인덱스 활용**: `price`와 `stock_quantity`처럼 실무에서 빈번하게 `AND` 조건으로 결합 조회되는 컬럼은 결합 인덱스(Composite Index)를 생성하여 쿼리 성능을 비약적으로 높일 수 있습니다.

## # 실습 예제 13 : OR 연산자 (합집합) 여러 값 중 하나라도 만족하는 조건 조회하기

OR 연산자는 여러 조건 중 하나라도 해당되면 조회합니다. 선택의 폭을 넓힐 때 사용합니다. `reviews` 테이블에서 평점(`rating`)이 3점 또는 4점인 리뷰의 상품번호와 평점을 조회합니다.

### 13.1 OR 조건 검색 쿼리

```sql
-- 평점이 3점 또는 4점인 리뷰의 상품번호, 평점 조회
SELECT product_id, rating
FROM reviews
WHERE rating = 3 OR rating = 4;
```

> 🎯 **핵심 배움 포인트 (OR 연산과 IN 연산자 연계)**:
> - **하나라도 만족 (합집합)**: 나열된 조건 중 어느 하나만 참이어도 결과에 포함되므로 검색 대상 범위(결과 행 수)가 확장됩니다.
> - **IN 연산자로의 확장**: 동일한 컬럼에 대해 여러 값을 `OR`로 나열하는 패턴(`rating = 3 OR rating = 4`)은 추후 다룰 `WHERE rating IN (3, 4)` 형태로 치환하면 코드가 간결해지고 가독성이 향상됩니다.

## # 실습 예제 14 : NOT 연산자 (부정) 특정 조건을 제외하는 조회하기

NOT 연산자는 특정 조건을 부정할 때 사용합니다. 즉, 조건에 해당하지 않는 데이터를 조회할 때 사용합니다. `products` 테이블에서 재고가 0이 아닌 상품의 상품명을 조회합니다.

### 14.1 NOT 조건 검색 쿼리

```sql
-- 재고가 0이 아닌 상품의 상품명 조회
SELECT name
FROM products
WHERE NOT stock_quantity = 0;

-- 아래와 같이 비교 연산자(!=)를 써도 결과는 같지만, NOT은 복잡한 조건을 부정할 때 유용합니다.
SELECT name
FROM products
WHERE stock_quantity != 0;
```

> 🎯 **핵심 배움 포인트 (NOT 연산자와 부정 비교 연산자 비교)**:
> - **조건의 반전**: `NOT` 연산자는 뒤따르는 조건식의 평가 결과를 반대로 바꿉니다(`TRUE` ↔ `FALSE`).
> - **!= 와의 비교 및 활용성**: 단순 값 비교의 경우 `!=` 또는 `<>` 연산자가 직관적이지만, `NOT IN`, `NOT BETWEEN`, `NOT LIKE` 등 범위나 집합 조건을 부정할 때는 `NOT` 연산자가 매우 강력하고 유연하게 쓰입니다.
> - **NULL 주의 (3치 논리, Three-Valued Logic)**: `stock_quantity`가 `NULL`인 데이터는 `stock_quantity = 0`도 아니고 `stock_quantity != 0`도 아닙니다(결과가 `UNKNOWN`). 따라서 `NOT`을 사용하더라도 `NULL` 행은 조회되지 않으며, NULL 데이터까지 포함하려면 `IS NULL` 조건을 별도로 다루어야 합니다.

## 4.1 IT 분야에서 NULL의 진짜 의미

많은 사람이 NULL을 숫자 0이나 빈 문자열(`''`)과 혼동합니다. 하지만 SQL에서 NULL은 **'아직 정의되지 않은 값'** 또는 **'알 수 없는 값(Unknown)'**을 의미합니다.

| 구분 | 의미 | 비유 |
| :---: | :--- | :--- |
| **`NULL`** | 값을 모름, 정의되지 않음 | 아직 이름표가 붙지 않은 빈 상자 |
| **`0`** | 숫자 '0'이라는 데이터가 있음 | 상자 안에 '0'이라는 숫자가 들어있음 |
| **`'' (빈 문자열)`** | 입력은 되었으나 내용이 비어있음 | 상자 안에 '비어있음'이라는 메모가 들어있음 |

> 🎯 **핵심 배움 포인트 (NULL의 특성과 3치 논리)**:
> - **연산 불가**: `NULL + 100`, `NULL * 2`와 같이 NULL이 포함된 산술 연산의 결과는 항상 `NULL`이 됩니다.
> - **비교 불가**: `NULL = 0`, `NULL = ''` 등의 비교 결과는 `TRUE`나 `FALSE`가 아닌 **`UNKNOWN`**입니다.
> - **Oracle의 예외적 특성**: 표준 SQL에서는 빈 문자열 `''`과 `NULL`을 구분하지만, **Oracle Database는 빈 문자열 `''`을 `NULL`로 취급**합니다.

## # 실습 예제 17 : 이메일이 없으면 '미입력'으로 표시하기

> 🎯 **핵심 배움 포인트 (NVL 함수와 NULL 대체값 처리)**:
> - **NVL(컬럼명, 대체값)**:
>   - 컬럼 데이터가 `NULL`이면 두 번째 매개변수로 전달된 **대체값**을 반환하고, `NULL`이 아니면 원래 컬럼 값을 그대로 반환합니다.
> - **데이터 타입 일치 필수 원칙**:
>   - 첫 번째 인자의 데이터 타입과 두 번째 대체값의 데이터 타입은 반드시 호환되어야 합니다. (예: `email`이 문자형이므로 대체값도 `'미입력'` 문자형 지정 / 숫자형 컬럼인 경우 `NVL(stock_quantity, 0)` 형태로 지정)
> - **가독성 향상과 비즈니스 보고서 활용**:
>   - 최종 출력 화면이나 보고서에 `(null)` 상태 대신 `'미입력'`, `'확인요망'`, `'0원'` 등 사용자가 직관적으로 이해할 수 있는 텍스트로 치환할 때 필수적으로 활용됩니다.

## # 실습 예제 18 : 특정 기간에 가입한 고객 조회하기

2025년 2월 한 달 동안 가입한 고객을 찾아보겠습니다. `BETWEEN` 연산자와 `TO_DATE` 함수를 사용하여 지정한 시작일부터 종료일 사이에 가입한 고객을 조회합니다.

### 18.1 BETWEEN 범위 조건 검색 쿼리

```sql
-- 2025년 2월 한 달 동안 가입한 고객 조회
SELECT customer_id, name, registered_date
FROM customers
WHERE registered_date BETWEEN TO_DATE('2025-02-01', 'YYYY-MM-DD')
                          AND TO_DATE('2025-02-28', 'YYYY-MM-DD');
```

> 🎯 **핵심 배움 포인트 (BETWEEN 연산자와 날짜 범위 검색 주의점)**:
> - **경계값 포함 (이상 & 이하)**:
>   - `컬럼 BETWEEN A AND B`는 `컬럼 >= A AND 컬럼 <= B`와 동일하며, 시작값(`A`)과 끝값(`B`)을 모두 포함합니다.
> - **시간(Time) 성분 주의사항**:
>   - `TO_DATE('2025-02-28', 'YYYY-MM-DD')`는 기본적으로 `2025-02-28 00:00:00`을 의미합니다.
>   - 따라서 컬럼에 시/분/초 데이터(예: `2025-02-28 14:00:00`)가 들어있다면 `00:00:00`보다 큰 시간이므로 2월 28일 당일 오후 데이터가 누락될 수 있습니다.

---

## 💡 개발자 note!

### 날짜 조회 시 "시간"이라는 복병을 조심하세요!

BETWEEN은 범위 조건에 매우 편리하지만, 날짜 컬럼에 시간이 포함되어 있는지 반드시 확인해야 합니다.

#### ❶ DATE 타입 컬럼의 특징 (Oracle 기준)
DATE 타입은 날짜 + 시간(시:분:초) 정보를 모두 포함합니다. 하지만 `TO_DATE('2025-02-28', 'YYYY-MM-DD')`처럼 날짜만 지정하면 Oracle은 내부적으로 이를 `2025-02-28 00:00:00`으로 변환합니다. 따라서 BETWEEN의 종료값으로 사용할 경우, 해당 날짜 자정 이후(`00:00:01 ~ 23:59:59`)에 저장된 데이터는 조회되지 않을 수 있습니다.

#### ❷ 주의사항
컬럼이 `TIMESTAMP` 타입이거나, 비교 값에 `TO_TIMESTAMP()`처럼 시간까지 포함된 경우에는 종료 시점이 `2025-02-28 00:00:00`이라면, 2월 28일 데이터는 누락될 수 있습니다.  
예를 들어 다음 쿼리는 오전 0시까지만 포함하기 때문에 데이터 누락의 위험이 있습니다.

```sql
-- 문제 발생 가능 : 종료 시간이 00:00:00 이므로 2월 28일 데이터 누락 위험
WHERE registered_date
BETWEEN TO_TIMESTAMP('2025-02-01 00:00:00', 'YYYY-MM-DD HH24:MI:SS')
    AND TO_TIMESTAMP('2025-02-28 00:00:00', 'YYYY-MM-DD HH24:MI:SS');
```

#### ❸ 가장 안전한 날짜 범위 조건 표현
종료일에 하루를 더한 뒤, **'미만(`<`)'** 조건을 사용하는 것이 가장 정확합니다.

```sql
-- 안전한 표현 방식
WHERE registered_date >= TO_DATE('2025-06-01', 'YYYY-MM-DD')
  AND registered_date <  TO_DATE('2025-07-01', 'YYYY-MM-DD');
```

정리하면 다음과 같습니다.

| 컬럼 타입 | 구현 방식 |
| :---: | :--- |
| **`DATE 타입`** | 날짜만 지정해도 Oracle이 자동으로 하루 전체 범위를 포함함 |
| **`TIMESTAMP 타입`** | 시간까지 명시된 경우, 범위 끝의 시각을 명확히 지정해야 함 |
| **`안전한 방법`** | `>= 시작일 AND < 다음날` |

날짜 조건을 지정할 때는 항상 **"해당 컬럼에 시간까지 저장되어 있는가?"**를 먼저 확인하는 습관이 중요합니다. 단순히 `BETWEEN`을 사용했다가 원하는 데이터가 누락되는 오류는 실무에서 매우 흔한 실수 중 하나입니다. 특히 보고서, 정산, 통계 등 정확한 기간 필터링이 중요한 업무에서는 `BETWEEN` 대신 **`>= 시작일 AND < 다음날`** 방식으로 명확하게 지정하는 것이 가장 안전합니다.

## # 실습 예제 19 : 특정 평점이나 상품 ID 필터링하기

rating이 1 또는 5인 리뷰를 조회합니다. `IN` 연산자를 사용하여 여러 후보 값 중 일치하는 데이터만 선별합니다.

### 19.1 IN 연산자 조건 검색 쿼리

```sql
-- 리뷰 점수가 1점 또는 5점인 리뷰 조회
SELECT review_id, customer_id, product_id, rating, content, created_at
FROM reviews
WHERE rating IN (1, 5);
```

> 🎯 **핵심 배움 포인트 (IN 연산자와 다중 OR 조건 대체)**:
> - **다중 OR 조건의 단순화**: `WHERE rating IN (1, 5)`는 `WHERE rating = 1 OR rating = 5`와 논리적으로 완전히 동일합니다. 비교 대상 값이 늘어날수록 `IN` 연산자를 사용하는 것이 쿼리의 가독성을 월등히 향상시킵니다.
> - **서브쿼리 확장**: `IN` 괄호 내부에는 상숫값 목록뿐 아니라 `IN (SELECT ...)` 형태의 서브쿼리를 사용할 수 있어 복잡한 연관 데이터 조회 시 강력한 도구로 활용됩니다.

## # 실습 예제 20 : 특정 상품 번호만 조회하기

상품 ID가 1, 3, 5인 상품만 조회합니다. `products` 테이블에서 기본키(`product_id`)를 기준으로 다중 건의 특정 상품을 일괄 추출합니다.

### 20.1 식별자 IN 조건 검색 쿼리

```sql
-- 상품 ID가 1, 3, 5인 상품만 조회
SELECT product_id, name, price
FROM products
WHERE product_id IN (1, 3, 5);
```

> 🎯 **핵심 배움 포인트 (식별자 IN 조회와 인덱스 최적화)**:
> - **PK 컬럼과 IN 연산자**: 기본키(Primary Key)인 `product_id`에 `IN (1, 3, 5)`를 적용하면 Oracle 옵티마이저는 각 ID마다 인덱스를 고속 탐색(Index Unique Scan 등)하여 대용량 테이블에서도 밀리초 단위로 데이터를 찾아옵니다.
> - **실무 다중 선택 API 구현**: 장바구니에 담긴 선택 상품 목록 조회, 관리자 화면에서 체크박스로 선택된 특정 고객/상품 상세 정보 일괄 조회 등에 가장 널리 쓰이는 표준 패턴입니다.
